1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
The Compliance Management Platform (CMP) is a multi-tenant web application
designed for organizations that operate across multiple physical locations
(stores, warehouses, offices, factories) and need to track, verify, and audit
regulatory licenses and compliance documents.

4. MULTI-TENANCY, RBAC & LOCATION SCOPING
--------------------------------------------------------------------------------
Every organization is isolated by org_id across database tables and API routes.

Roles (Prisma enum Role):
1. ORG_ADMIN
   - Full visibility and control across all locations in their organization.
   - Can create locations, create/update/delete users, assign locations to
     managers, verify/reject documents, and manage audit rooms.
2. LOCATION_MANAGER
   - Scoped strictly to locations assigned via UserLocationAccess.
   - Can view assigned locations, complete/update operational store details
     (PATCH /api/tenancy/locations/:locationId, protected by
     authorizeRoles('ORG_ADMIN', 'LOCATION_MANAGER') and verifyLocationAccess),
     and upload/manage documents for assigned locations.
3. EXTERNAL_INSPECTOR
   - Read-only external role for inspecting shared compliance records.

Location Profile Completion Workflow:
- Locations can be provisioned with basic details and marked
  profile_completed = false.
- When a Location Manager signs in or opens the location, CompleteLocationModal
  allows them to fill in store code, facility type (STORE, WAREHOUSE, OFFICE,
  FACTORY), state, city, GSTIN, PIN code, contact phone, employee count,
  operating hours, and full address.
- Once type, state, and address are present, profile_completed automatically
  updates to true in tenancyService.updateLocation.


5. DATABASE SCHEMA (PRISMA MODELS & ENUMS)
--------------------------------------------------------------------------------
Enums:
- Role: ORG_ADMIN, LOCATION_MANAGER, EXTERNAL_INSPECTOR
- DocumentStatus: PENDING_VERIFICATION, VERIFIED, REJECTED, EXPIRED
- AlertType: EXPIRY_WARNING, LAPSED_LICENSE, CASCADING_RISK
- NotificationChannel: EMAIL, SMS, IN_APP

Models:
1. Organization (organizations)
   - Stores org metadata: id, name, tax_id (unique), industry, website, phone,
     address, timestamps.
2. Location (locations)
   - Stores facility metadata: id, org_id, name, code (unique per org), type,
     state, address, city, pincode, phone, gstin, employee_count,
     operating_hours, profile_completed, current_compliance_score.
3. User (users)
   - Stores id, org_id, name, email (unique), password_hash, role, timestamps.
4. UserLocationAccess (user_location_access)
   - Join table mapping user_id <-> location_id (unique pair).
5. LicenseType (license_types)
   - Catalog of regulatory licenses: name, code (unique, e.g., TRADE_LICENSE,
     FIRE_NOC, PAN, DGFT_IEC), description, issuing_authority,
     default_validity_months, is_lifetime_valid.
6. Dependency (dependencies)
   - Maps license_type_id -> prerequisite_license_type_id with is_blocking flag.
7. LicenseTypeStateRule (license_type_state_rules)
   - State-level overrides for is_mandatory and validity_override_months.
8. RequiredLicenseType (required_license_types)
   - Maps which license_type_id is required per location_type and optional state.
9. ComplianceScore (compliance_scores)
   - Stores historical score snapshots per location: score (0-100),
     breakdown_json, calculated_at.
10. Document (documents)
    - Stores file_name, storage_key, file_size, mime_type, sha256_hash,
      issue_date, expiry_date, status, rejection_reason, uploaded_by_id,
      verified_by_id, verified_at, parent_document_id (self-referencing renewal
      chain), and optional location_id (null for org-wide documents).
11. AuditLink (audit_links)
    - Stores unique token, optional pin_hash, title, notes, expires_at,
      is_active, created_by_id.
12. AuditLinkDocument (audit_link_documents)
    - Join table linking an AuditLink to selected Document records.
13. AuditLinkAccessLog (audit_link_access_logs)
    - Tracks accessed_at, ip_address, user_agent, and success flag.
14. NotificationLog (notification_logs) & NotificationPreference
    (notification_preferences)
    - Tracks sent alerts and per-user email/SMS/in-app opt-ins by AlertType.


6. CORE WORKFLOWS
--------------------------------------------------------------------------------
A. Document Upload & Verification
   - Files are uploaded via multipart/form-data (Multer) to the configured S3
     bucket through StorageService.
   - A SHA-256 hash is computed at upload time and stored for integrity.
   - New uploads start in PENDING_VERIFICATION.
   - Admins review and mark documents VERIFIED or REJECTED (with reason).
   - Renewals link back to the previous document via parent_document_id,
     preserving a full audit trail in VersionHistoryModal.

B. Compliance Score & Dependency Engine
   - Evaluates required licenses for a location based on its facility type and
     state rules.
   - Checks whether each required license has a valid, non-expired VERIFIED
     document.
   - Evaluates prerequisite dependencies: if a blocking prerequisite license is
     missing or expired, dependent licenses are flagged with cascading risk.
   - Produces a 0-100 score, actionable suggestions, and persists snapshots in
     ComplianceScore for trend visualization.

C. Audit Data Rooms
   - Org Admins select specific documents and generate a time-bound AuditLink.
   - External inspectors open /audit/:token, enter a PIN if configured, and
     view/download only the shared documents.
   - Every access attempt is recorded in AuditLinkAccessLog.

D. Automated Scheduling & Alerts
   - node-cron runs periodic sweeps to mark expired documents as EXPIRED,
     recalculate compliance scores, and dispatch EXPIRY_WARNING,
     LAPSED_LICENSE, or CASCADING_RISK alerts via in-app logs and email.


7. ENVIRONMENT VARIABLES (backend/.env)
--------------------------------------------------------------------------------
Required:
- PORT                     API server port (default: 5000)
- NODE_ENV                 development | production | test
- DATABASE_URL             PostgreSQL connection URI (special characters in
                           passwords such as '?' must be URL-encoded as '%3F')
- JWT_SECRET               Secret key for signing JWTs
- JWT_EXPIRES_IN           Token lifetime (e.g., 7d)

Storage (STORAGE_PROVIDER = 's3' or 'minio'):
- S3 mode: AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_S3_BUCKET,
  AWS_REGION, and optional S3_ENDPOINT (for Supabase Storage S3)
- MinIO mode: MINIO_ENDPOINT, MINIO_ACCESS_KEY, MINIO_SECRET_KEY,
  MINIO_BUCKET, MINIO_REGION

Email (EMAIL_PROVIDER = 'resend' or 'nodemailer'):
- Resend mode: RESEND_API_KEY, RESEND_FROM
- Nodemailer mode: SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, SMTP_FROM

CORS:
- CORS_ORIGIN              Allowed frontend origin (default: http://localhost:5173)
